**One-command complete regeneration (no CI):**

```bash
cd experiments
python extra5_regenerate_all.py
```

This regenerates JSONs, the binary 9,360×20 candidate-ticket cache and updated PNG plots under `../figures/`. It reuses the committed 100-draw historical dataset, does not download fresh draws and may overwrite derived files. For a minimal rerun use the commands below.

**Manual run order:**

```bash
python extra5_mass_algorithm_benchmark.py
python extra5_mass_algorithm_calibration.py
```

The benchmark generates `extra5_mass_algorithm_results.json`, 9,360-row scores CSV and `extra5_mass_algorithm_holdout_masks.npz` in this directory; calibration then generates its Monte Carlo outputs and chart. The CSV included here is the recorded result from the original run. Both diagnostic JSON files and four regenerated PNG/SVG figures are committed. The **binary NPZ intermediate cache is intentionally not tracked in Git**: it is deterministic and regenerated by the benchmark. PNG figures under `../figures/` are research-data-based rerenders, not byte-for-byte copies of earlier screenshots. See reports and project documentation for preserved numerical results. A synthetic demonstration file (`extra5_test_synthetic.csv`) is **not** lottery history; do not use it for empirical claims.

**Evidence:** The synthetic candidates are NOT the actual EXTRA 5 RNG system; no candidate showed reliable predictive ability or compromised a system. The 20 later historical draws were known before model evaluation; not prospective predictions.
